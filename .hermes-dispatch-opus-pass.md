## Task 1 — KNOWN BUG (fix it)

**Clicking a window does not raise it**: the z-index of a window doesn't change when clicked, so a clicked window doesn't come to the front. Current state:
- `Window.tsx` sets `zIndex: isActive ? 30 : 10` — but `isActive` only updates when the shell's `activeWindowId` changes, and the shell only updates that on taskbar clicks, NOT on window body/title clicks.
- `Window.tsx` has `isFocused` state + a `useEffect` on `isActive`, and the drag handler raises nothing.

Required behavior: mousedown/pointerdown ANYWHERE on a window (title bar or body) raises it above all other windows immediately. Implement via an `onFocus`/`onPointerDown`-driven raise callback (e.g. `onFocusChange` prop wired from WindowsShell's setActiveWindowId), or a self-managed z-index counter like the approved mock uses (`focusWindow` pattern). Also ensure keyboard focus (tabbing into a window) raises it. Keep it simple and correct — no new deps.

While there: check the drag handler (`handleMouseDown` in Window.tsx) — after a drag completes, verify the window keeps its raised z-index.
